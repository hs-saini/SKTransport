S K TRANSPORT WEBSITE AUR PWA - VISTAR SE HINDI GUIDE
======================================================

Yeh guide project ke maujooda source code ko padhkar taiyar ki gayi hai.
Isme website ke pages, JavaScript functions, design, API, admin security,
tests, PWA files, Git aur Vercel ka kaam samjhaya gaya hai.

Zaroori sachchai:
- Website ka poora purana development history Git files se hamesha maloom
  nahi hota. Isliye yeh guide maujooda code aur dekhe ja sake Git state ka
  varnan karti hai; yeh dawa nahi karti ki website ka har purana hissa isi
  session mein banaya gaya tha.
- Is session mein PWA setup add hua: manifest, service worker registration,
  app icons aur Apple touch icon.
- Is session mein Git push ya Vercel deployment nahi kiya gaya. Ant mein
  push/redeploy ke sahi steps diye gaye hain.
- Is guide ya source ke zariye password, secret, Blob token ya private
  credential share nahi kiya gaya hai.


1. WEBSITE KA SARAL NAKSHA
--------------------------

Visitor ke browser mein:

  index.html
      +-- styles.css       rang, layout, responsive design aur animation
      +-- script.js        Hindi/English, booking form, fleet, settings aur admin UI
      +-- manifest.json    browser ko website ko installable app batata hai
      +-- sw.js            app ki zaroori static files cache karta hai
      +-- PNG icons        app install hone par icon dikhate hain

Vercel par server side:

  /api/admin-session  -> api/admin-session.js -> server/admin.js
  /api/settings       -> api/settings.js      -> server/admin.js
                                                   + @vercel/blob

Tests:

  tests/admin-api.test.js -> login, session, input aur settings API ki jaanch

Yeh React/Vue application nahi hai. Front end seedha HTML, CSS aur browser
JavaScript hai. `api` folder ke handlers Vercel par serverless functions ke
roop mein chalte hain; alag `server.js` file is repository mein nahi hai.


2. WEBSITE KHOLNE PAR KYA HOTA HAI
---------------------------------

1. Browser `index.html` download karke page ka dhaancha dikhata hai.
2. `styles.css` desktop/mobile layout aur rang lagata hai.
3. `script.js` HTML ke khaali dynamic containers bharta hai: fleet cards,
   routes, service cards aur menu links.
4. Script pehle default business settings dikhata hai aur `/api/settings`
   se shared settings laane ki koshish karta hai.
5. Browser visitor ko English ya Hindi chunne deta hai. Chunav localStorage
   mein yaad rakha jata hai.
6. Booking par email bhejne ki koshish hoti hai; saath mein WhatsApp/SMS ka
   message taiyar hota hai jise visitor khud review karke bhej sakta hai.
7. Admin login alag server API se verify hota hai. Safal login ke baad
   settings save karne ki API ko authenticated request bheji jaati hai.
8. Normal public page par service worker register hota hai aur static
   app-shell cache kiya ja sakta hai.


3. `index.html` - PAGE KA DHAANCHA
----------------------------------

`<!doctype html>` browser ko HTML5 mode mein rakhta hai.
`<html lang="en">` page ki default bhasha batata hai. JavaScript ise Hindi
chunne par `hi` kar deta hai.

`<head>` ke important kaam:
- `charset` UTF-8 Hindi aur doosre akshar sahi dikhata hai.
- `viewport` mobile screen ke size ke mutabik page scale karta hai.
- `theme-color` browser/app ke theme rang ko blue karta hai.
- `rel="manifest"` `/manifest.json` ko PWA settings se jodta hai.
- icon links browser tab aur Apple home screen ke icons dete hain.
- description, canonical, Open Graph aur Twitter meta tags search aur
  social-sharing preview ke liye hain.
- JSON-LD mein `LocalBusiness`, location, phone aur service area diya gaya
  hai, jisse search engine ko business ka structured data milta hai.
- Google Fonts ke preconnect/font links heading, body aur Hindi font laate
  hain. Font network unavailable ho to CSS fallback fonts hain.
- `styles.css` visual design load karta hai.

`<body>` ke mukhya hisse:
- Announcement bar: seva aur availability ka chhota banner.
- Header/brand: logo-style SVG, business naam, language buttons, navigation
  aur booking link.
- Hero: bada headline, call/book buttons aur inline SVG truck illustration.
- Ticker: vehicle types ki chalti hui patti.
- Services/fleet: JavaScript `#fleet-grid` ko gाड़ियों ke cards se bharta hai.
- Capabilities: `#capability-grid` mein service cards; click karne par form
  mein service chuni ja sakti hai.
- Pan-India strip: booking section tak pahunchne ka shortcut.
- Routes: `#routes-grid` mein suggested routes; button pickup/drop bharte hain.
- About: business ka parichay, owner aur inline SVG truck art.
- Booking: vehicle, service, contact, pickup, destination aur doosri details
  lene wala form.
- Contact strip: pata, phone aur available email contacts.
- Footer: links, contact aur admin trigger.
- WhatsApp floating link: script phone number ke mutabik link update karta hai.
- Admin `<dialog>`: login form aur settings dashboard ka HTML; aam public
  visitor ko admin-only CSS ke bina dashboard nahi dikhaya jata.
- Ant ka `script.js` link front-end functionality chalata hai.

`data-i18n`, `data-i18n-html`, `data-i18n-placeholder`, `data-i18n-aria`
aur `data-i18n-label` attributes translations ke keys hain. IDs, jaise
`booking-form`, `fleet-grid` aur `routes-grid`, JavaScript ko sahi element
dhoondhne dete hain.

Form ke `required`, `maxlength`, `type=email`, `type=tel`, checkbox consent
aur `reportValidity()` basic browser validation dete hain. Phone ke digits
ki extra jaanch JavaScript karta hai.

- `.hero`, `.hero-art`, `.hero-truck`, `.road`, `.sun-disc`, `.speed-lines`

  `.booking`, `.contact-*` page ke alag sections/cards/forms ko style karte

- `.admin-*` selectors dialog, login, dashboard, vehicle/menu/route editors

- `.footer-*` aur `.whatsapp-float` footer aur floating WhatsApp button hain.
- `.hindi` selectors Hindi font aur text ke liye kuch size/spacing badalte hain.

5. `script.js` - FRONT-END JAVASCRIPT KE FUNCTIONS
-------------------------------------------------

Shuruaat ek IIFE `( () => { ... })()` se hoti hai. Isse variables global
browser namespace mein nahi phailte. `"use strict"` JavaScript ke sakht
niyam chalu karta hai.

Service worker registration:
- `isAdminPage` URL ke `?admin=1` query ko check karta hai.
- Normal public site mein `navigator.serviceWorker.register("/sw.js")` chalta
  hai. Admin iframe/view ke liye registration nahi karte.
- Registration fail ho to `console.error` mein asal error dikhate hain;
  error chupakar success nahi dikhate.

Settings aur constant groups:
- `DEFAULT_MENU_ITEMS`, `DEFAULT_ROUTES`, `DEFAULTS`: API response na milne
  par dikhane ke liye business, fleet, menu aur route defaults.
- `MENU_TARGETS`, `MAX_MENU_ITEMS`, `MAX_ROUTES`: admin form ke valid targets
  aur maximum list limits.
- `SERVICE_OPTION_INDEX`: capability card se booking dropdown ka sambandh.
- `TEXT`, `FEATURE_TEXT`: English aur Hindi ke UI strings.
- `VEHICLE_COPY`, `VEHICLE_ICONS`, `VEHICLE_PHOTOS`: fleet cards ka
  description, decorative symbol aur default image.

Translation aur DOM helpers:
- `$ (selector, root)` ek matching element dhoondhta hai
  (`querySelector` ka chhota helper).
- `$$ (selector, root)` sab matching elements ko array banata hai.
- `t(key)` chuni hui bhasha ka text leta hai; feature strings, English
  fallback aur ant mein key fallback ka kram hai.
- `applyLanguage()` document lang/title/meta ko update karta hai; har
  `data-i18n*` element par sahi text/placeholder/ARIA label lagata hai.
  Iske baad fleet, service, menu aur route content dobara render hota hai.
- `[data-language]` buttons click listener bhasha badalta hai; localStorage
  mein selection rakhne ki koshish hoti hai.
- `safeText(value)` HTML special characters ko escape karta hai, taaki
  settings se bana text markup/script na ban jaye.
- `formatPhone(value)` 10 digit phone ko padhne layak 5+5 format deta hai.
- `validPhotoUrl(value)` vehicle photo URL ko HTTPS hona zaroori karta hai.
- `defaultVehiclePhoto(index)` Unsplash photo list se default image URL deta hai.

Settings:
- `loadSettings()` defaults ki alag copy aur gaadiyon ki default photos banata hai.
- `normalizeSettings(saved)` API se aayi settings ko type, list limit,
  image URL, menu target aur route ke hisab se normalize karta hai.
- `requestSharedSettings()` same-origin `/api/settings` GET request karta hai;
  HTTP failure par error throw karta hai.
- `refreshSharedSettings()` settings laakar page render/translate karta hai.
  Network/API error ko console mein spasht log karta hai; initial defaults
  page par reh sakte hain.
- `renderSettings()` business, owner, address, phone links, email, fleet,
  routes/menu aur WhatsApp ko current settings se update karta hai.
- `updateWhatsAppLink()` floating WhatsApp aur driver contact ke liye
  number aur Hindi/English message lagata hai.

Page ke dynamic sections:
- `renderCapabilities()` capability cards banata hai; mouse click, Enter ya
  Space par booking form tak le jaakar relevant service chunta hai.
- `renderServiceHighlights()` chhote highlight labels/icon banata hai.
- `menuTargetLabel(href)` admin menu target ko English/Hindi naam deta hai.
- `renderMenuItems()` header/footer menu links ko settings se banata hai.
- `renderRoutes()` routes dikhata hai. Route button pickup/drop fields bharta
  hai aur form tak scroll karta hai.
- `renderServiceOptions()` language ke hisab se service `<select>` options
  dobara banata aur selection ko jahan mumkin ho banaye rakhta hai.
- `renderFleet()` photo cards aur vehicle radio choices banata hai. Pehle
  chuni gaadi preserve hoti hai; card click/keyboard se radio select hota hai.
  Image fail ho to fallback photo; fallback bhi fail ho to unavailable state.

Booking:
- `composeMessage(data)` form values ko selected language mein readable
  multiline booking message banata hai.
- `smsLink(number, message)` phone/message ko SMS URL mein encode karta hai;
  iOS aur doosre devices ke separator ka farq rakhta hai.
- `whatsappUrl(number, message)` number ko digits mein normalize karta hai,
  10-digit number par India code jodta hai, aur message URL-encode karta hai.
- `sendBookingEmail(data, message)` FormSubmit AJAX endpoint ko JSON bhejta
  hai. Optional alternate email alag ho to CC deta hai. Network, unreadable
  JSON, provider failure aur activation pending ko error banata hai.
- `showBookingActions(result, message)` WhatsApp, SMS aur clipboard buttons
  banata hai. Clipboard fail ho to console log aur UI fallback dikhata hai.
- `#booking-form` submit listener: default browser submit rokta hai,
  browser validation chalata hai, 10+ phone digits maangta hai, data padhta
  hai, double submit rokta hai, button disable karta hai, email send karta
  hai aur result/fallback links dikhakar button wapas enable karta hai.
- Email provider request website se bahar FormSubmit ko jaati hai. Booking
  email provider ki activation agar required ho to business ko activation
  email confirm karni pad sakti hai.

Admin interface:
- `setLoginMode()` login copy, submit label aur purana error clear karta hai.
- `fillSettingsForm()` server settings GET karke admin inputs/vehicle/menu/
  route editors bhar deta hai.
- `renderAdminMenuItems()` bilingual menu inputs aur valid destination select
  banata hai; input/change/remove events internal list ko update karte hain.
- `renderAdminRoutes()` route start/end inputs banata hai; edit aur remove
  events list ko update karte hain.
- `renderAdminVehicles()` vehicle name/photo editor, preview aur remove
  button banata hai; HTTPS photo validation aur kam-se-kam ek vehicle rule hai.
- `translateAdminVehicles()` remove button ke text/accessible label ko
  current language mein update karta hai.
- `showDashboard()` server se settings load karta hai; failure par admin
  error dikhata hai, safal hone par login chhupakar dashboard dikhata hai.
- `openAdminDialog()` login screen set karke modal kholta hai.
- `#admin-auth-form` POST `/api/admin-session` karta hai; server ka error
  dikhata hai, safal par password form reset aur dashboard load karta hai.
- Add vehicle/menu/route listeners duplicate/limit/empty checks karte hain,
  nayi row banate hain aur uske input par focus dete hain.
- `#settings-form` submit browser validation ke baad cleaned settings object
  banata hai, PUT `/api/settings` bhejta hai, response ko normalize/render
  karta hai aur error/success ko dikhata hai.
- Logout DELETE `/api/admin-session` karta hai; server confirmation ke baad
  dialog band karta hai. Failure chupaya nahi jata.
- Dialog close listener admin-only page se website par lautata hai.
- `visibilitychange` par tab dobara visible ho to shared settings refresh hoti hai.
- Menu toggle mobile nav kholta/band karta hai aur `aria-expanded` update karta hai.
- Footer service clicks dropdown mein service set karte hain.
- `#year` current copyright year lagata hai.
- `IntersectionObserver` scroll par sections/cards ko reveal karta hai.
- `matchMedia` pointer/reduced-motion check karke desktop pointer movement
  se hero art ko halka parallax deta hai ya motion ko band rakhta hai.

7. `sw.js` - SERVICE WORKER AUR OFFLINE APP SHELL
-------------------------------------------------

- `CACHE_NAME` version-named cache hai. Naya version purane project caches
  ko activate par hata sakta hai.
- `APP_SHELL` homepage, HTML/CSS/JS, manifest aur icons ki fixed list hai.
- `install` event cache kholta, poori app-shell list ko cache karta aur cache
  kamyab hone par naya worker activate karne ko kehta hai.
- `activate` purane `sk-transport-shell-*` caches delete karta aur naye
  worker ko open pages ka control lene deta hai.
- `fetch` event sirf same-origin, GET, bina query wali requests intercept karta.
- Homepage navigation pehle network se milti hai; network unavailable ho to
  cached `/index.html` milta hai.
- Static files cache mein hon to cache se aati hain; cache miss par network
  se fetch hota hai.
- API, POST/PUT/DELETE, third-party requests aur query-string requests is
  caching rule se exclude hain. Isse admin/API responses ko offline cache
  karne ka jokhim nahi liya gaya.
- Agar install ke samay cache list ki file uplabdh na ho, service worker
  install fail ho sakta hai; browser console aur DevTools Application tab
  is tarah ki dikkat dekhne ki jagah hain.

Offline mode poori backend service offline nahi banata. Admin API, live
settings, booking email aur external vehicle photos ko network chahiye ho
sakta hai. Offline mein cached page khulna aur sab external features ka
chalna ek hi baat nahi.


8. `api/admin-session.js` - ADMIN LOGIN API
-------------------------------------------

Yeh Vercel serverless handler hai; `server.js` naam ki standalone file nahi.
`handler(req, res)` HTTP method ke mutabik:
- GET: signed session cookie jaanchkar `authenticated` status deta hai.
- POST: same-origin, server configuration aur rate limit check karta hai;
  username/password match par session cookie banata hai.
- DELETE: session cookie expire karke logout karta hai.
- doosre method: HTTP 405 aur allowed method list deta hai.
- Login body galat JSON ho to HTTP 400; galat credentials HTTP 401;
  zyada attempts HTTP 429; secret/storage configuration taiyar na ho to 503.
- Cookie value response JSON mein nahi bheji jaati; cookie HTTP-only hai.


9. `api/settings.js` - SHARED SETTINGS API
------------------------------------------

`handler(req, res)`:
- GET: public page ko business settings dene ke liye storage configured ho
  to private Blob se settings padhta hai. Nayi installation/default case
  mein `DEFAULT_SETTINGS` de sakta hai. Read/storage problem par 503.
- PUT: same-origin aur authenticated admin session dono maangta hai.
  Configuration missing ho to 503.
- Body ko `validateSettings()` se jaanchta, private Blob mein save karta aur
  safal saved settings return karta hai.
- Galat input ke liye 400; storage failure ke liye 503; unsupported method
  ke liye 405.
- Browser ko private Blob token dene ke bajaye server-side handler hi
  credential use karta hai.


10. `server/admin.js` - SHARED SECURITY/STORAGE HELPERS
------------------------------------------------------

- `DEFAULT_SETTINGS`: pehli baar ya data na milne par business/fleet/menu/
  route defaults.
- `respond(res, status, data, headers)`: JSON response, `no-store`,
  `nosniff` aur referrer-policy headers set karke response bhejta hai.
- `setCookie(...)`: HTTP-only, SameSite Strict, `/api` path aur expiry ke
  saath cookie set karta hai; Vercel production par Secure flag bhi hota hai.
- `isSameOrigin(req)`: Origin/host/protocol compare karke cross-site
  mutation rokne mein madad karta hai.
- `credentialsConfigured()`: password length aur session-signing secret ki
  minimum readiness check karta hai.
- `equalSecret(...)`: barabar length check ke baad constant-time
  `timingSafeEqual` istemal karta hai.
- `sessionSignature(payload)`: HMAC-SHA256 se session payload sign karta hai.
- `readCookie(req)`: request se admin cookie alag karta hai.
- `hasAdminSession(req)`: signature verify, payload parse aur expiry check
  karta hai; malformed/expired cookie ko valid nahi maanta.
- `requireSameOrigin(...)`, `requireAdminSession(...)`: API mein common
  security guard; na-manzur request par 403/401 bhejte hain.
- `adminConfigurationReady()` aur `settingsConfigurationReady()`:
  Vercel Blob aur auth secrets configured hone ki jaanch.
- `readJsonBody(req)`: object body leta ya string JSON parse karta hai.
- `text(...)`, `email(...)`, `phone(...)`: trim, required/optional,
  maximum length aur format/digits validate karte hain.
- `validateSettings(value)`: object size (64 KiB), vehicle count/photos,
  menu targets/count, routes/count, HTTPS image URLs aur business fields
  validate karke sirf expected fields ka clean object return karta hai.
- `readSharedSettings()`: private Blob se JSON laata hai; absent data par
  clone kiye defaults deta hai.
- `writeSharedSettings(settings)`: dobara validate karke private Blob par
  shared settings overwrite karta hai.
- `clientKey(req)`: rate limit ke liye forwarded IP ya remote address chunta hai.
- `checkLoginRateLimit(req)`: temporarily blocked client ko rokta hai.
- `recordLoginFailure(req)`: galat login count karta; paanch failures par
  15 minute block lagata hai. Badi in-memory list ko purane entries se saaf
  karta hai. Serverless workers alag hon to in-memory limit har worker ka
  apna state ho sakta hai.
- `clearLoginFailures(req)`: sahi login par us client ka failure state hatata hai.
- `createSessionCookie(res)`: random nonce aur 8-hour expiry wala signed session
  cookie banata hai.
- `clearSessionCookie(res)`: cookie ko zero max-age se khatam karta hai.
- `credentialsMatch(username, password)`: Vercel env credentials verify karta;
  default username `admin` ho sakta hai, password env secret se hi aata hai.
- `isPasswordConfigured()`: auth readiness batata hai.

`@vercel/blob` ki `get` aur `put` server-side par private settings JSON
padhne/save karne ke liye import hoti hain.

15. IS KAAM MEIN AAYI ASAL DIKKATEIN AUR UNKA HAL
-------------------------------------------------

Pehle diye gaye PWA snippet mein HTML tag galat tha: manifest link ke
`href` mein `/heme-color` tha aur usi `<link>` par `content` attribute diya
gaya tha. Use do sahi tags mein alag kiya:
  <link rel="manifest" href="/manifest.json">
  <meta name="theme-color" content="#0d6efd">

Suggested `public` folder yahan use nahi kiya, kyunki project ka static
homepage aur assets Vercel root se serve hote hain. Root files ke URL
`/manifest.json`, `/sw.js` aur `/icon-192.png` hote hain.

Logo image 256x256 thi jabki PWA ko 192x192 aur 512x512 icons chahiye the.
